# Page Host Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `PageStack` pushes pages through an `IPageHost` that creates and places the page controls (Kibinago's
`PageHost` panel, `FakePageHost` in tests), so a drill-down screen writes no `PushXxx` / `RemovePage` plumbing.

**Architecture:** Core gains `Kibinago.Views.IPageHost` (`AddPage(Type, title, services)`, `RemovePage(view)`);
`PageStack(owner, Func<IPageHost>)` and `bool Push(page[, param], title)` replace the explicit-view overloads; every
former `removeView` call goes to `host.RemovePage`. The WinForms `PageHost` creates views through
`IViewMappingRegister.WithServiceProvider(services)` (the Navigator's lookup), whose type-based registration now
accepts any `Control`. The check policy, busy rules, window close and external release of #81 are unchanged.

**Tech Stack:** C# (LangVersion latest), netstandard2.0 (Core / Testing), net472 + net10.0-windows (Kibinago), xUnit
2.9.3 on net48 (CI), local net10 harness for non-WinForms tests.

**Spec:** `docs/superpowers/specs/2026-11-05-page-host-design.md` (authority; read first). Background, unchanged:
`docs/superpowers/specs/2026-11-04-page-stack-design.md`.

## Global Constraints

- Public API change is exactly: + `Kibinago.Views.IPageHost`; `PageStack(IPresenter, Func<IPageHost>)` replaces
  `PageStack(IPresenter)`; `bool Push<TView>(ControlPresenterBase<TView>, string title)` and
  `bool Push<TView,TParam>(ControlPresenterBase<TView,TParam>, TParam, string title)` (both `where TView : class,
  IControlView`) replace the four-/five-argument `void Push`; + `Kibinago.Views.PageHost` (WinForms);
  + `Kibinago.Testing.FakePageHost`; `IViewMappingRegister.Register<TI, TImpl>()` constraint `Form` → `Control`.
  No shims, no other public member; still nothing new on presenter base classes.
- Whoever does not use `PageStack` must not notice anything (windows, `AttachChild`, Navigator unchanged).
- Existing tests from before #81 are not edited, except `ApiSurfaceTests`' view-interface list (adding `IPageHost`,
  intended). #81's own tests are migrated.
- `Kibinago.Core` has no WinForms reference; XML docs on every public member (build error otherwise).
- wiki / CHANGELOG / sample UI in Japanese; code, comments, spec, plan in English.
- Never run anything on the Windows host; net48 / WinForms tests run on CI (push only after asking the owner).
- AntdUI trial (Task 6) is local only: never pushed, never sent to codex / artifacts.
- Execution: native, TDD per task, codex review after each task (herdr pane `pagestack-review`), one fresh
  whole-branch reviewer at the end.

## Review Focus

1. A host whose `AddPage` throws midway (mapping missing, control constructor throws) → `Push` throws, `Count`
   unchanged, the host shows the previous top, nothing to undo in the stack. (Task 1, Task 3)
2. A view rejected after `AddPage` (wrong type / claimed / services rejected) → `RemovePage` once, the page presenter
   stays undisposed and pushable elsewhere. (Task 1)
3. A page that disposes itself in `OnInitialize` → `Push` returns `false`, its view removed once; owner disposed during
   the push → `false`, nothing removed. (Task 1)
4. Under M.E.DI, a page view registered only in the container with a scoped dependency gets the page presenter's
   scope. (Task 3)
5. A `PagesChanged` handler (the view's breadcrumb redraw) that pushes or pops → rejected (stack busy), no corruption.
   (Task 1, Task 3)
